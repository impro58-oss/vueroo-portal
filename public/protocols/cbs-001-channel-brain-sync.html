CBS-001 Channel-Brain Sync

Department: CBS (Channel-Brain Sync) Status: NEW

Protocol — Channel Brain Sync (CBS-001)

Created: 2026-08-16 02:40 IST

Version: 1.0

Status: ACTIVE

Purpose

Every Telegram channel linked to Lumina's brain automatically syncs conversation data to the correct brain domain. No manual trigger required. Works for all mapped channels.

Architecture — Three Layers

Layer 1: Rolling Update (Real-Time)

When: Every time Lumina replies in a mapped channel.

What: Append the exchange (user message + Lumina reply summary) to the channel's conversation log.

Where: memory/channel-conversations/<channel-slug>-log.md

Process:

  1. After composing a reply but before sending, Lumina appends to the conversation log:
  • Message number (sequential)
  • Timestamp
  • Sender
  • Content summary (not full text — key points, decisions, topics discussed)
  • Any files created/modified
  1. This happens as part of the reply flow, not as a separate step.

Rule: If a channel has a mapping file in memory/channel-mappings/, rolling updates are ON. If no mapping file exists, the channel is unmapped and no logging occurs.

Layer 2: Cron Safety Net (Passive Sweep)

When: Every 4 hours (6x per day)

What: Scan all mapped channels for conversation gaps. Pull recent session history and append any exchanges not yet logged.

Where: Cron job, script at scripts/channel-brain-sync.py

Process:

  1. List all mapping files in memory/channel-mappings/
  1. For each mapped channel:

a. Read the mapping file → get channel ID, session key, log file path

b. Pull recent session history (last 50 messages)

c. Read the current conversation log

d. Compare — find any messages in history not yet in the log

e. Append missing exchanges with summaries

f. Sync updated log to vault (if vault path specified in mapping)

  1. Log run status to memory/channel-sync-status.md

Why: Catches anything missed by Layer 1 — session crashes, mid-conversation interruptions, messages where Lumina replied with NO_REPLY, etc.

Layer 3: Session Start Replay

When: When Lumina wakes in a mapped channel (first message of a new session)

What: Read the conversation log + mapping file → load context → summarize last N exchanges in the log as internal context.

Where: Part of the boot sequence defined in each channel mapping file.

Process:

  1. Detect channel ID from inbound metadata
  1. Check memory/channel-mappings/ for a matching file
  1. If found:

a. Read mapping file → identify brain domain, mode, context files

b. Read conversation log → get last 10-20 exchanges

c. Load context files specified in mapping

d. Enter the correct mode

e. Internal summary: "Continuing from [date] — last topic was [X], key decisions were [Y]"

  1. If no mapping found: default mode, no special context loading

File Structure

Cron Job Specification

Name: channel-brain-sync

Schedule: Every 4 hours (0 /4 )

Script: scripts/channel-brain-sync.py

Log: memory/channel-sync-status.md

Adding a New Channel

  1. Create memory/channel-mappings/<channel-slug>.md using the template
  1. Create memory/channel-conversations/<channel-slug>-log.md with header
  1. Sync both to vault (if vault path specified)
  1. The cron job automatically picks up new mappings — no config change needed
  1. Rolling updates automatically activate — no flag to set

Rules

  • Conversation logs store SUMMARIES, not full message text. Full text lives in session history.
  • If a channel has no mapping file, it's ignored by all three layers.
  • Vault sync is optional per channel (specified in mapping file).
  • The cron script reads mapping files dynamically — adding a new mapping file is all that's needed.
  • Conversation logs are append-only. Never rewrite history. If a correction is needed, add a new entry noting the correction.

This protocol is universal. It works for any channel that has a mapping file. No per-channel setup beyond creating the mapping file itself.
