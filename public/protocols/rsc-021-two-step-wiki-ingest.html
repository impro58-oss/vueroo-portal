RSC-021 — Two-Step Wiki Ingest Protocol

Purpose: Improve the quality of knowledge base ingests by splitting source processing into two phases — analysis, then generation — rather than single-pass reading and writing.

Inspired by: Karpathy's LLM Wiki pattern + nash_su's llm_wiki two-step chain-of-thought ingest.

When This Protocol Applies

  • Processing a research article (URL, PDF, LinkedIn post)
  • Processing a VOC/VOT transcript
  • Processing a book chapter or extraction
  • Any task where a new source needs to be integrated into the wiki/vault

Does NOT apply to: Quick lookups, fact checks, or single-question queries that don't produce wiki pages.

Phase 1 — Analysis (Read & Plan)

The LLM reads the source and produces a structured analysis WITHOUT writing any wiki pages.

Step 1.1: Read Source

  • Read the full source (article, transcript, PDF)
  • Note: key entities, concepts, arguments, data points

Step 1.2: Check Existing Wiki

  • Search the relevant domain for existing pages on the same topic
  • Identify: which existing pages should be updated? which new pages should be created?
  • Check the domain index.md for navigation

Step 1.3: Produce Analysis Document

Output a structured analysis (in chat or a temp file) containing:

## Source Analysis: [Title]

### Key Entities
- [Entity 1]: [what this source says about it]
- [Entity 2]: [what this source says about it]

### Key Concepts
- [Concept 1]: [definition/finding from this source]

### Key Data Points
- [Metric]: [value] — [source citation]
- [Metric]: [value] — [source citation]

### Contradictions with Existing Wiki
- [Page X] says [old claim]; this source says [new claim] — resolution: [which is more reliable?]
- (If none: "No contradictions found")

### Recommended Page Updates
- UPDATE [existing-page-1]: add [data point] to [section]
- UPDATE [existing-page-2]: revise [claim] based on [new evidence]
- CREATE [new-page-1]: [why this needs its own page]
- CREATE [new-page-2]: [why]

### Cross-References to Add
- Link [page A] ↔ [page B] because [reason]
- Link [page C] → [new source] because [reason]

### Strategic Relevance
- [How this source impacts strategy decisions]
- [What action it suggests]

Step 1.4: Review with User (if interactive)

  • Present the analysis to Roo for review
  • Adjust based on feedback
  • For auto-process (research article default): skip review, proceed to Phase 2

Phase 2 — Generation (Write & Link)

The LLM takes the analysis and produces wiki updates.

Step 2.1: Write Source Summary Page

  • Create a source summary with YAML frontmatter (title, date, source, tags)
  • Include: key findings, methods, data points, limitations
  • Save to the appropriate domain folder

Step 2.2: Update/Create Entity & Concept Pages

  • UPDATE existing pages: add new data, revise claims, add cross-references
  • CREATE new pages: only if the concept is significant enough to warrant its own page
  • Every page gets [[wikilinks]] to related concepts

Step 2.3: Update Index

  • Run python scripts/wiki-index-generator.py [domain-dir] to regenerate the domain index
  • Or manually add entries to index.md if the script is unavailable

Step 2.4: Log the Ingest

  • Append to the domain log (or session log) with format:

## [YYYY-MM-DD] ingest | [Source Title] | [pages touched]

Step 2.5: Flag Contradictions

  • If contradictions were found, add a "⚠ Contradiction" section to the affected page
  • Note both claims, sources, and which is more recent/reliable
  • Add to the review queue for next lint pass

Auto-Process Mode (Research Articles)

When Roo sends a research article (URL/LinkedIn) and the "auto-execute all" behavior is active:

  1. Phase 1 runs automatically (web_fetch → analyze → no user review)
  1. Phase 2 runs automatically (brain note → vault → cross-refs → index update)
  1. Telegram brief sent with summary
  1. All four default actions completed (research + brief + brain note + update D/E)

The two-step structure improves quality because:

  • Phase 1 forces the LLM to think about WHERE new information fits before writing
  • Phase 2 executes against a plan, not from scratch
  • Cross-referencing is systematic, not opportunistic

Quality Checks

  • [ ] Every new page has at least 2 [[wikilinks]] to existing pages
  • [ ] Every updated page notes what changed and why
  • [ ] Numbers include source citations (author, year, or DOI)
  • [ ] Contradictions are flagged, not silently resolved
  • [ ] Index.md is regenerated after ingest
