1. PURPOSE & SCOPE

What BlackWatch Is

BlackWatch is a continuous global intelligence system that monitors 20 domains (financial, geopolitical, cyber, energy, social, etc.), detects convergence patterns where multiple domains reinforce each other, and produces structured situational awareness for decision support.

What BlackWatch Is Not

  • Not a prediction system
  • Not a trading signal generator
  • Not an automated decision maker
  • Not a news aggregator
  • Not a replacement for human judgment

Scope Boundaries

  • In scope: Data collection, signal processing, convergence detection, dashboard rendering, scan generation, memory evolution
  • Out of scope: Automated trading, external messaging, financial transactions, autonomous action on findings

Technology Stack

Layer Technology Rationale
Data collection Python 3.11 + urllib Minimal dependencies, runs anywhere
Data format JSON Human-readable, browser-native, no DB needed
Scheduling OpenClaw cron Already running, proven, 6h cadence
Dashboard Static HTML + Tailwind CSS + Vanilla JS Same as CycleVue, proven pattern
Hosting Vercel (vueroo-portal) Already deployed, CDN, auto-build on git push
Rendering D3.js (optional for Phase 2) For convergence visualization
State File-based JSON No database — simple, portable, debuggable

Why No Database

BlackWatch produces ~50KB of JSON per refresh. A database adds operational complexity without value at this scale. JSON files are:

  • Human-readable (can inspect in text editor)
  • Git-trackable (version history of signal data)
  • Instantly deployable (push to Vercel, CDN serves)
  • Debuggable (no query layer between data and inspection)

If signal volume grows beyond 10MB per scan (unlikely before 2027), migrate to SQLite.

    │

  "Run BlackWatch Morning Echo scan"
    │

    ├──► Checks for signal flips (green→amber, amber→red)

4. COMPONENT SPECIFICATION

4.1 Connector Layer

blackwatch-fred-connector.py

  • Input: FRED API key (from environment or hardcoded)
  • Output: blackwatch-signals.json
  • Run cadence: Every 6 hours via cron
  • Timeout: 300 seconds (5 min)
  • Dependencies: Python standard library only (urllib, json, os, datetime)
  • Failure mode: If FRED API is down, outputs last-known-good data with stale flag

blackwatch-news-connector.py (Phase 2)

  • Input: NewsAPI key, GDELT API
  • Output: blackwatch-news.json (event log + sentiment)
  • Run cadence: Every 6 hours
  • Purpose: Geopolitical events, social sentiment, cyber incidents

blackwatch-crypto-connector.py (Phase 2)

  • Input: CoinGecko API (no key needed)
  • Output: blackwatch-crypto.json
  • Run cadence: Every 6 hours
  • Purpose: BTC dominance, stablecoin flows, DeFi TVL

6. FAILURE MODES & RECOVERY

6.1 FRED API Down

Symptom Detection Recovery
HTTP timeout or 5xx from FRED Connector catches exception, logs error Uses last-known-good JSON (stale flag set)
Rate limited (429) Connector catches HTTP 429 Waits 60s, retries once, then fails gracefully

Recovery procedure:

  1. Connector writes {"stale": true} flag to JSON
  1. Dashboard shows "STALE DATA" badge on signal tiles
  1. Next cron run retries automatically
  1. If FRED down > 12h (2 missed runs), Lumina alerts Roo

6.2 Vercel Deployment Fails

Symptom Detection Recovery
Git push succeeds but Vercel build fails Vercel webhook (Phase 4) or manual check Previous deployment remains live
JSON not served (404) Dashboard fetch fails Dashboard shows cached data with warning

Recovery procedure:

  1. Vercel keeps previous deployment live — no downtime
  1. Check Vercel dashboard for build errors
  1. Fix code, push again
  1. Verify new deployment at /blackwatch

6.3 Cron Job Fails

Symptom Detection Recovery
Agent session times out OpenClaw cron logs show failure Next cron run retries
Script error (Python crash) Agent reports error Fix script, run manually, then let cron resume
FRED API key invalid All fetches fail Rotate API key, update script

Recovery procedure:

  1. Check cron list for last-run status
  1. Read cron run logs for error details
  1. Fix root cause
  1. Run script manually: python scripts/blackwatch-fred-connector.py
  1. Verify JSON output
  1. Let cron resume on next schedule

6.4 Dashboard JavaScript Error

Symptom Detection Recovery
Blank section or broken rendering Browser console shows JS error Fix code, push to git
Data not loading (fetch fails) Console shows 404 or CORS error Check Vercel routing + JSON path
Stale data (not refreshing) Data timestamp old Check cron job status

Recovery procedure:

  1. Open browser console (F12) on /blackwatch
  1. Identify error from console output
  1. Fix in local files
  1. node -c syntax check
  1. Git commit + push
  1. Hard refresh browser

6.5 Data Corruption

Symptom Detection Recovery
JSON parse error Dashboard JS catches and logs Re-run connector
Impossible values (e.g., VIX = -5) Validation in connector Connector validates ranges

Recovery procedure:

  1. Delete corrupted JSON
  1. Re-run connector: python scripts/blackwatch-fred-connector.py
  1. Verify output: python -c "import json; d=json.load(open('data/blackwatch-signals.json')); print(d['metadata'])"
  1. Git push

6.6 Signal Drift (Indicators Stop Updating)

Symptom Detection Recovery
FRED series discontinued Last date > 30 days old Find replacement series on FRED
Manual signals never updated Manual signals show 0 confidence for > 7 days Prompt Roo for assessment

Recovery procedure:

  1. Check FRED series page — is it still active?
  1. Search FRED for replacement series
  1. Update SIGNALS dict in connector script
  1. Test fetch
  1. Update dashboard if series_id display changes

7. MONITORING & SELF-HEALING

Self-Healing Rules

Condition Action
FRED API timeout Retry once after 60s, then use cached data
FRED series discontinued Log warning, mark signal as "stale", alert on next scan
JSON write fails Retry with fallback path (workspace only)
Git push fails Log error, data still written locally, next cron will retry push
Dashboard fetch fails Show cached data with "STALE" badge, auto-retry in 60s
Cron job fails 3x consecutive Lumina alerts Roo in next session
