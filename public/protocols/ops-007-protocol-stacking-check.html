OPS-007 Protocol Stacking & Pre-Generation Check

Department: OPS (Operations) — Cross-Cutting

Version: 1.0

Created: 2026-07-07

Owner: Lumina

Status: ACTIVE

Trigger: Before generating ANY deliverable (report, document, dashboard, code, presentation)

Purpose

This protocol exists because on 2026-07-07, I generated a VOC report for Dr. Link using only RPT-009 (the content protocol) while ignoring MEDTECH-VOC-PROCEDURAL-SPECIFICATION (the visual/layout specification). The result was a simplified memo instead of the proper 9-section VOC extraction report with pain point matrices, confidence scores, and strategic conclusions. The user caught it. It should not have happened.

The root cause: I treated the protocol search as "find THE protocol" instead of "find ALL related specifications." This protocol makes the stacking check a forced step before any deliverable generation begins.

When to Apply

Before generating ANY deliverable, including but not limited to:

  • VOC reports (RPT-008, RPT-009 + Procedural Specification)
  • MedTech research reports (RPT-001)
  • Trading analysis reports (RPT-002)
  • Business plans (RPT-003)
  • Presentations (RPT-004)
  • Injury journal reports (RPT-010)
  • Professional communications (RPT-007)
  • Any Word document, PDF, dashboard, or code deliverable

The Stacking Check (MANDATORY — Execute Before Generation)

Step 1: Identify the Deliverable Type

Determine what type of deliverable you are about to produce. Name it explicitly.

Step 2: Search for ALL Related Protocols and Specifications

Run memory_search with at least three query patterns:

  1. "<protocol ID> protocol specification" (e.g., "RPT-009 protocol specification")
  1. "<deliverable type> specification standard format" (e.g., "VOC report specification standard format")
  1. "<deliverable type> procedural layout" (e.g., "VOC procedural layout specification")

Read EVERY matching file. Do not stop at the first match.

Step 3: Classify What You Found

For each file found, determine:

  • Content protocol — tells you WHAT to write (sections, structure, quality gates)
  • Visual specification — tells you HOW it must look (fonts, colours, margins, tables, headers/footers)
  • Style guide — tells you what LANGUAGE conventions to use (British English, tone, formatting)
  • Reference example — shows you a completed output to match against

You need ALL applicable files before you may begin generation.

Step 4: Verify Completeness

Before starting generation, confirm:

  • [ ] Content protocol loaded? (WHAT sections to write)
  • [ ] Visual specification loaded? (HOW it must look — fonts, colours, layout)
  • [ ] Language standard confirmed? (British English — see Language Standard below)
  • [ ] Product name reference loaded? (if MedTech — device name normalisation)
  • [ ] Reference example reviewed? (if one exists)
  • [ ] OPS-006 Anti-Sloppy-Work protocol loaded? (verification steps after generation)

If ANY item is missing, search again before proceeding. Do not assume a specification doesn't exist just because the first search didn't surface it.

Step 5: Document the Stack

In your first progress update, list the protocols/specifications you are following:

Protocol Stack:
- Content: RPT-009 (VOC Call Notes)
- Visual: MEDTECH-VOC-PROCEDURAL-SPECIFICATION (9-section layout, fonts, colours)
- Language: British English (OPS-007)
- Product Names: wp-product-names-reference.md
- Verification: OPS-006 (Anti-Sloppy-Work)

Language Standard: British English

All written deliverables must use British English spelling and conventions. This applies to:

  • All RPT protocols (RPT-001 through RPT-010)
  • All VOC reports and call notes
  • All MedTech research reports
  • All professional communications (RPT-007)
  • All injury journal reports (RPT-010)
  • All trading analysis reports (RPT-002)
  • All business plans (RPT-003)
  • All presentations (RPT-004)
  • All daily briefs and syntheses (RPT-005, RPT-006)

Punctuation and Formatting

  • Use single quotation marks for primary quotations, double for nested: 'He said "go" and I left'
  • Dates: 7 July 2026 (not July 7, 2026) in body text; 2026-07-07 in metadata/filenames
  • Times: 14:30 (24-hour) or 2.30 pm (with full stop, not colon)
  • Numbers: spell out one to nine, use figures for 10+
  • Per cent (two words), not percent
  • While (meaning "although"), not whilst

Tone

Professional, clinical, precise. No Americanisms. No colloquialisms unless quoting verbatim. When quoting a speaker who uses American English, preserve their exact words in the quote but use British English in all surrounding prose.

Enforcement

This protocol is enforced by the Pre-Generation Check. No deliverable may be generated until the stacking check is complete and documented. If a deliverable is produced without the stacking check, it is a violation of OPS-006 (Anti-Sloppy-Work) as well as OPS-007.
