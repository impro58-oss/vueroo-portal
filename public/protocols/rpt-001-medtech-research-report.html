RPT-001 MedTech Research Report Protocol

Department: RPT (Reporting) Version: 1.0 Created: 2026-05-25 Owner: Lumina Status: DRAFT

Purpose

Write a MedTech intelligence report that is accurate, properly sourced, and clearly tagged. These reports feed NeuroVue, the 6B Doorway Platform, and investor/partner communications. Errors in MedTech reports are reputationally expensive — this protocol prevents them.

Trigger

  • When writing any MedTech competitive intelligence document
  • When preparing a white paper, market brief, or clinical summary
  • When updating NeuroVue dashboard data

    • Prerequisites

  • Research completed per RSC-002 (MedTech Literature Review)
  • All data points tagged as VERIFIED/ESTIMATE/UNVERIFIED/0.1
  • Target audience identified (internal, investor, regulatory, clinical)

    • Steps

    Step 1: Define Report Scope

    Fill in this template BEFORE writing: 
    
Report: [Title]
Audience: [Internal / Investor / Regulatory / Clinical / Partner]
Purpose: [What decision does this report support?]
Date Range: [What period does the data cover?]
Confidence Level Required: [HIGH = all claims verified / MEDIUM = some estimates OK]

    Step 2: Structure the Report

    Use this standard structure:

    markdown

    [Report Title]
    Date: YYYY-MM-DD
Author: Lumina (with Roo oversight)
Classification: [Internal / Confidential / Public]
Version: 1.0
    Executive Summary
    
[3-5 sentences. What is the key finding? What should the reader DO?]
    Key Findings
    
1. [Finding 1] — [VERIFIED/ESTIMATE] — (Author, Year)
2. [Finding 2] — [VERIFIED/ESTIMATE] — (Author, Year)
3. [Finding 3] — [VERIFIED/ESTIMATE] — (Author, Year)
    Market Context
    
[Market size, growth rate, key players. All financial data tagged. Harvard citations required.]
    Clinical Evidence
    
[Study results, complication rates, outcomes. Harvard citations required — include study type, sample size, and full reference.]
    Competitive Landscape
    
[Competitor profiles, product comparisons, strategic positions. Harvard citations for all claims.]
    Strategic Implications
    
[What this means for us. What actions to take.]
    Data Quality Notes
    
[What is VERIFIED vs ESTIMATE vs UNVERIFIED. Gaps in knowledge.]
    References
    
[Harvard reference list. Alphabetical by author. Every entry cited in-text.]
    Appendix
    
[Raw data tables, methodology notes.]

    Step 3: Write Each Section

    Market Context rules:

  • Revenue figures: ONLY use published financial data, tagged [VERIFIED], cited Harvard style e.g., (Medtronic, 2025)
  • If revenue is estimated from multiple company reports: tag [ESTIMATE: derived from X, Y, Z sources] and cite each e.g., (Medtronic, 2025; Stryker, 2025)
  • If no data exists: use 0.1 marker, NEVER fabricate a number
  • Growth rates: cite source and time period e.g., (GlobalData, 2024)
  • Market share: cite source, note methodology e.g., (Evaluate Vantage, 2025)

    • Clinical Evidence rules:

  • Follow RSC-002 tagging exactly
  • Include study type and sample size for every statistic, cited Harvard style e.g., (Turjeman et al., 2024)
  • Note limitations of the evidence
  • Distinguish between "proven" and "promising"
  • Never present company marketing claims as clinical evidence
  • Include DOI or URL for every cited study

    • Competitive Landscape rules:

  • Distinguish between [VERIFIED] public filings and [UNVERIFIED] company claims
  • Include regulatory status (FDA clearance, CE mark) with dates and citations e.g., (FDA, 2024)
  • Note pipeline products separately from approved products
  • Include pricing only if from verified source, cited Harvard style

    • Step 4: Tag and Citation Review

    After writing, scan the ENTIRE report for:
    Every numerical claim has a tag
    No tag is missing (if unsure, tag [ESTIMATE])
    No financial estimates without explicit ESTIMATE tag
    No clinical claims without Harvard citation and study reference
    No company marketing claims presented as facts
    Every in-text citation has a matching reference list entry (no orphans)
    Every reference list entry is cited in-text (no ghosts)
    Reference list is alphabetical by first author surname
    All web sources include "Accessed" date

    Step 5: Source Archiving

    Every source cited in the report must be archived locally. If a source cannot be downloaded automatically, it must be flagged for manual download by Roo.

    Archive location: Documents/MedTech Intell/[Project]/References/

    Archive process:

    
For each reference in the reference list:

1. Can the source be downloaded as PDF?
   YES → Download and save to References/ folder
         Filename format: AuthorYear_ShortTitle.pdf
         e.g., Turjeman2024_WEB17_TenYearOutcomes.pdf

2. Is it a web page (no PDF)?
   YES → Save as PDF from browser (Ctrl+P → Save as PDF)
         OR use web_fetch to extract text and save as .txt

3. Is it behind a paywall or requires login?
   YES → Add to MANUAL-DOWNLOAD.md with:
         - Full Harvard reference
         - URL
         - Reason it can't be auto-downloaded
         - Priority: URGENT / HIGH / NORMAL
         - Note: "Download by Roo"

4. Is it a company annual report?
   YES → These are usually free. Download PDF from investor relations page.
         Filename: CompanyName_AnnualReport_YYYY.pdf

5. Is it a clinical trial (ClinicalTrials.gov)?
   YES → Save the trial summary page as PDF or text.
         Include NCT number in filename.
         e.g., NCT01234567_WEB_IntracranialAneurysm.pdf

    Step 6: Quality Gate — Three Gates Verification

    Gate 1: Accuracy

  • Every fact traceable to a source?
  • Every number matches its source?
  • No fabricated data?

    • Gate 2: Logic

  • Does the argument follow from the evidence?
  • Are conclusions supported, not assumed?
  • Are alternative explanations acknowledged?

    • Gate 3: Utility

  • Does this answer the question that triggered the report?
  • Can the reader take action based on this?
  • Is the executive summary actionable?

    • Step 7: Multi-Model Review (if HIGH-stakes)

    For reports going to investors, partners, or public: 1. Run key findings through a second model (Claude or Perplexity) 2. Ask: "What's wrong with this analysis? What am I missing?" 3. Incorporate corrections, document the review

    Step 8: Deliver

  • Save to Obsidian: 20-Areas/MedTech-NeuroVue/Reports/
  • Save source PDFs to: Documents/MedTech Intell/[Project]/References/
  • If any sources could not be auto-downloaded: create MANUAL-DOWNLOAD.md in References/ folder and flag for Roo
  • If updating NeuroVue: update JSON data files, push to GitHub
  • If for investor/partner: export as PDF, review with Roo before sending

    • Quality Gates

    All data points tagged [VERIFIED]/[ESTIMATE]/[UNVERIFIED]/[0.1]
    No financial estimates without ESTIMATE tag
    All citations are Harvard style (author-date)
    No orphan citations (in-text with no reference) or ghost references (reference with no in-text citation)
    All cited sources archived in References/ folder (PDFs or text extracts)
    MANUAL-DOWNLOAD.md created if any sources require manual download
    Three Gates passed (Accuracy, Logic, Utility)
    Multi-model review completed (if HIGH-stakes)
    Filed in correct Obsidian location

    Error Handling

    | Error | Response | |-------|----------| | Missing data for a section | Write "Data not available — [GAP]" not "approximately X" | | Conflicting sources | Present both, note conflict, flag for Roo | | Section doesn't apply | Write "Not applicable to this report" — don't skip silently | | Source cannot be downloaded | Add to MANUAL-DOWNLOAD.md with full Harvard reference, URL, and priority level | | Source URL is dead (404) | Search for archived version (Wayback Machine), note in Data Quality Notes if unavailable |

    Harvard Referencing Standard

    All RPT-001 reports use Harvard (author-date) referencing. No other style is acceptable. Every in-text citation must have a matching reference list entry, and vice versa.

    In-Text Citation Format

    
Single author:     (Smith, 2024)
Two authors:       (Smith and Jones, 2024)
Three+ authors:    (Smith et al., 2024)
Specific page:     (Smith, 2024, p. 47)
Multiple sources:  (Smith, 2024; Jones, 2023)
No author:         (WHO, 2024)
Direct quote:      (Smith, 2024, p. 47)

    Reference List Format

    Journal article:
    Smith, J.A. and Jones, B.C. (2024) 'Title of the article', Journal Name, 12(3), pp. 45–67. doi: 10.xxxx/xxxxx.

    Book:
    Levin, R.C. (2023) Biotech in the Balance: Trust as a Strategic Differentiator. Boston: Harvard Business Review Press.

    Web source:
    WHO (2024) Global Stroke Fact Sheet. Available at: https://www.who.int/... (Accessed: 26 May 2026).

    Company report / annual report:
    Medtronic plc (2025) Annual Report 2025. Dublin: Medtronic plc. Available at: https://www.medtronic.com/... (Accessed: 26 May 2026).

    Clinical trial:
    Turjeman, A. et al. (2024) 'WEB 17: Ten-year outcomes of the WEB device for treatment of intracranial aneurysms', Stroke, 55(4), pp. 1023–1031. doi: 10.1161/STROKEAHA.123.123456.

    Conference presentation:
    Gomez, J. (2025) 'Pipeline embolization: five-year results', presented at the International Stroke Conference 2025, Los Angeles, 12 February.

    Rules

    Every factual claim with a source must have an in-text citation
    Reference list must be alphabetical by first author surname
    Every in-text citation must appear in the reference list — no orphans
    Every reference list entry must be cited in-text — no ghosts
    Use "et al." for 3+ authors in-text, list all authors in reference list
    Include DOI or URL for every source that has one
    Include "Accessed" date for all web sources
    Tag estimates and unverified claims separately — citation does not equal verification
