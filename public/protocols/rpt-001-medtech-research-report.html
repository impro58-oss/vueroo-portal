RPT-001 MedTech Research Report Protocol

Department: RPT (Reporting) Version: 1.0 Created: 2026-05-25 Owner: Lumina Status: DRAFT

Purpose

Write a MedTech intelligence report that is accurate, properly sourced, and clearly tagged. These reports feed NeuroVue, the 6B Doorway Platform, and investor/partner communications. Errors in MedTech reports are reputationally expensive — this protocol prevents them.

Trigger

  • When writing any MedTech competitive intelligence document
  • When preparing a white paper, market brief, or clinical summary
  • When updating NeuroVue dashboard data

    • Prerequisites

  • Research completed per RSC-002 (MedTech Literature Review)
  • All data points tagged as VERIFIED/ESTIMATE/UNVERIFIED/0.1
  • Target audience identified (internal, investor, regulatory, clinical)

    • Steps

    Step 1: Define Report Scope

    Fill in this template BEFORE writing: 
    
Report: [Title]
Audience: [Internal / Investor / Regulatory / Clinical / Partner]
Purpose: [What decision does this report support?]
Date Range: [What period does the data cover?]
Confidence Level Required: [HIGH = all claims verified / MEDIUM = some estimates OK]

    Step 2: Structure the Report

    Use this standard structure:

    markdown

    [Report Title]
    Date: YYYY-MM-DD
Author: Lumina (with Roo oversight)
Classification: [Internal / Confidential / Public]
Version: 1.0
    Executive Summary
    
[3-5 sentences. What is the key finding? What should the reader DO?]
    Key Findings
    
1. [Finding 1] — [VERIFIED/ESTIMATE] — Source: [attribution]
2. [Finding 2] — [VERIFIED/ESTIMATE] — Source: [attribution]
3. [Finding 3] — [VERIFIED/ESTIMATE] — Source: [attribution]
    Market Context
    
[Market size, growth rate, key players. All financial data tagged.]
    Clinical Evidence
    
[Study results, complication rates, outcomes. All data tagged per RSC-002.]
    Competitive Landscape
    
[Competitor profiles, product comparisons, strategic positions.]
    Strategic Implications
    
[What this means for us. What actions to take.]
    Data Quality Notes
    
[What is VERIFIED vs ESTIMATE vs UNVERIFIED. Gaps in knowledge.]
    Sources
    
[Full citation list.]
    Appendix
    
[Raw data tables, methodology notes.]

    Step 3: Write Each Section

    Market Context rules:

  • Revenue figures: ONLY use published financial data, tagged [VERIFIED]
  • If revenue is estimated from multiple company reports: tag [ESTIMATE: derived from X, Y, Z sources]
  • If no data exists: use 0.1 marker, NEVER fabricate a number
  • Growth rates: cite source and time period
  • Market share: cite source, note methodology

    • Clinical Evidence rules:

  • Follow RSC-002 tagging exactly
  • Include study type and sample size for every statistic
  • Note limitations of the evidence
  • Distinguish between "proven" and "promising"
  • Never present company marketing claims as clinical evidence

    • Competitive Landscape rules:

  • Distinguish between [VERIFIED] public filings and [UNVERIFIED] company claims
  • Include regulatory status (FDA clearance, CE mark) with dates
  • Note pipeline products separately from approved products
  • Include pricing only if from verified source

    • Step 4: Tag Review

    After writing, scan the ENTIRE report for:
    Every numerical claim has a tag
    No tag is missing (if unsure, tag [ESTIMATE])
    No financial estimates without explicit ESTIMATE tag
    No clinical claims without study citation
    No company marketing claims presented as facts

    Step 5: Quality Gate — Three Gates Verification

    Gate 1: Accuracy

  • Every fact traceable to a source?
  • Every number matches its source?
  • No fabricated data?

    • Gate 2: Logic

  • Does the argument follow from the evidence?
  • Are conclusions supported, not assumed?
  • Are alternative explanations acknowledged?

    • Gate 3: Utility

  • Does this answer the question that triggered the report?
  • Can the reader take action based on this?
  • Is the executive summary actionable?

    • Step 6: Multi-Model Review (if HIGH-stakes)

    For reports going to investors, partners, or public: 1. Run key findings through a second model (Claude or Perplexity) 2. Ask: "What's wrong with this analysis? What am I missing?" 3. Incorporate corrections, document the review

    Step 7: Deliver

  • Save to Obsidian: 20-Areas/MedTech-NeuroVue/Reports/
  • If updating NeuroVue: update JSON data files, push to GitHub
  • If for investor/partner: export as PDF, review with Roo before sending

    • Quality Gates

    All data points tagged [VERIFIED]/[ESTIMATE]/[UNVERIFIED]/[0.1]
    No financial estimates without ESTIMATE tag
    Three Gates passed (Accuracy, Logic, Utility)
    Multi-model review completed (if HIGH-stakes)
    Filed in correct Obsidian location

    Error Handling

    | Error | Response | |-------|----------| | Missing data for a section | Write "Data not available — [GAP]" not "approximately X" | | Conflicting sources | Present both, note conflict, flag for Roo | | Section doesn't apply | Write "Not applicable to this report" — don't skip silently |
