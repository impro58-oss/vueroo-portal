RPT-013 — Board Member Intelligence Build Protocol

Department: RPT (Reports) / Board Architecture

Version: 1.0

Created: 2026-08-15

Owner: Lumina

Status: ACTIVE

Trigger: Any time a new board member (subject-matter expert advisor) is added to Roo's company board structure, or an existing board member's knowledge is upgraded.

Purpose

Define the EXACT, repeatable process for building each board member as a "body of intelligence" — a unique, individual advisor with its own persona, knowledge base, mind map, and brain linking. This protocol is modelled on the Paul Overy (Irish Wealth Expert) build, which is the proven template. Every board member is built the same way, so improvements made to one can be applied back to all.

Board concept: Roo is building a company board structure. Each board member is an individual, unique advisor giving advice from their own standpoint. Subject-matter experts are the guiding light; other board members give their angles and foresight. A board meeting = Roo + Lumina + N agents, each with the personality of a board member, sharing a synaptic mind (linked into the brain).

THE 6-STEP BUILD PROCESS

Every board member goes through these 6 steps, in order. Do NOT skip any.

Step 1: EXTRACTION

Extract ALL the source knowledge (books, courses, transcripts, PDFs, websites) into raw markdown.

  • Save raw extractions to memory/<board-member>-extractions/
  • Keep the full source text — do not truncate
  • Document the source list (books, authors, dates)

Step 2: CROSS-QUESTIONING

Cross-question the extracted knowledge to surface depth, examples, numbers, and stories.

  • Ask the source material targeted questions across every domain
  • Pull specific figures, rates, examples, and anecdotes (not just concepts)
  • Identify what's missing and fill gaps
  • Target depth: The knowledge base should be comprehensive (Paul's is ~57KB). A thin distillation (~12KB) is NOT acceptable.

Step 3: BUILD THE KNOWLEDGE RESOURCE

Create the structured knowledge base (memory/<board-member>-knowledge-base.md).

  • Organize into numbered sections by domain
  • Include: core premise, frameworks, specific numbers, examples, do's/don'ts, cross-references
  • Add a changelog section for future updates
  • Mirror to the vault: 20-Areas/Wealth/<Board-Member>/

Step 4: PRODUCE THE MIND MAP

Create the navigable mind map for Roo (per RPT-012 Mindomo format).

  • Minimum 3 levels of depth: Main topic → Module → Subtopic → Guidance
  • Every subtopic has a guidance line (what it means + an "Ask <Board Member>: ..." prompt)
  • Clean indentation format, no markers, no spaces in filename
  • Save to memory/research/<board-member>-extraction/

Step 5: LINK INTO THE BRAIN

Create a brain note in 90-System/Brain/<category>/ so the board member's knowledge is indexed, searchable, and connectable.

  • Brain note structure (mirror Paul's):
  • Date, category, tags, confidence
  • Summary
  • Key topics covered
  • Full knowledge base path
  • Gap-fill updates
  • Changelog
  • CRITICAL: The board member MUST be able to search the brain and answer from the full story. This is the "synaptic mind" — the linking is non-negotiable.

Step 6: WIRE THE AGENT

Create/update the agent script so the board member can be queried and can search the brain.

  • CLI query interface (like rich_dad_agent.py)
  • Loads persona + knowledge base
  • Can search the brain for connected context
  • Cross-references other board members where relevant

BOARD MEETING FORMAT

When Roo calls a board meeting (Roo + Lumina + N board members):

  1. Roo poses the subject/question.
  1. Each board member answers from their own standpoint (persona + knowledge base + brain search).
  1. Lumina synthesizes the best path, noting where the subject-matter expert is the guiding light and where other members add angles/foresight.
  1. Output: a board-meeting synthesis document.

IMPROVEMENT LOOP (Apply Back to All)

Any improvement made to one board member's build MUST be considered for application to all others:

  • New extraction technique → apply to all
  • Better mind map format → apply to all
  • Better brain linking → apply to all
  • New cross-questioning method → apply to all

Rule: When a board member is upgraded, check the other board members for the same upgrade. Do not let one member fall behind the standard.

VERIFICATION (OPS-006 — before declaring done)

  • [ ] Raw extractions exist and are complete
  • [ ] Knowledge base is comprehensive (not a thin distillation)
  • [ ] Mind map has 3+ levels of depth in correct Mindomo format
  • [ ] Brain note exists and links to the knowledge base
  • [ ] Agent script works and can search the brain
  • [ ] Vault mirror is in sync
  • [ ] All files verified on disk (read the actual output, not just the summary)
