Protocol PLN-001 — Pre-Execution Plan

ID: PLN-001

Type: Protocol (Behavioral)

Created: 2026-07-03

Status: Active

Replaces: dev-005-pre-execution-plan (namespace collision with DEV-005 API Integration)

Purpose

Before any task requiring more than 3 tool calls, produce a structured scaffold that forces explicit thinking about approach, risks, and verification before execution begins.

Procedure

When a task requires >3 tool calls, BEFORE executing any work:

  1. Generate a scaffold containing these nine elements (from AGENTS.md Stage 1):
  • Problem statement — What problem are we solving?
  • Success/verification criteria — How will we confirm it's done?
  • Governing protocol — Which protocol-*.md file applies?
  • Model selection — Which model tier (T1/T2/T3/etc.)?
  • Tools needed — Specific tools, not "I'll figure it out"
  • Memory/context to load — Which memory files are relevant?
  • Retry/recovery strategy — What if the first approach fails?
  • Constraints — Time, resources, limitations
  • Risk assessment — What could go wrong?
  1. Save the scaffold to memory/scaffold-active.md before executing.
  1. On completion, archive the scaffold to memory/scaffold-archive/ (create directory if needed).

When This Protocol Applies

  • Any task with >3 tool calls (not counting reads for orientation)
  • Triggered by: protocol up + task identification, or self-identified when planning
  • Does NOT apply to: simple lookups, single-file edits, conversational responses

Scaffold Evolution

This protocol is itself a learnable object. After execution, review the scaffold's accuracy:

  • Did the predicted tools/models/risks match reality?
  • What worked well in the scaffold? What failed?
  • Should this protocol be updated? If yes, propose specific change.
  • Log review via: python scripts/scaffold-review-logger.py log --protocol PLN-001 ...
  • Log benchmark via: python scripts/scaffold-benchmark.py log --task "..." --protocol PLN-001 ...
