RPT-010: Injury Journal Report Protocol

Standardized protocol for creating and updating injury journal reports for legal documentation

PRE-FLIGHT CHECK: Before creating or updating ANY injury journal report — read the previous version first. The previous report IS the ground truth. Check it first, then update.

0. Pre-Flight Check (MANDATORY)

Before creating or updating ANY injury journal report:

  1. Read the previous version of the report. Open the most recent .docx file in C:\Users\impro\Documents\NYC accident information\. Read its full structure, sections, and content. The previous report is the canonical baseline — all updates build from it.
  2. Read the Costs & Payments Ledger. Open NYC Accident Costs & Payments Ledger.xlsx. Every row must appear in the medical care log.
  3. Read all source journal files for the weeks being added or updated.
  4. Do NOT start from scratch. The previous report contains verified content, correct formatting, and cross-referenced data. Copy its structure and extend it.

1. Trigger

When Roo provides new week(s) of injury journal entries, or requests an update to the existing injury journal report.

2. Source Material Rules

  • ONLY use what Roo provides and what exists in the NYC accident information folder
  • Raw journal text is the ONLY truth
  • NEVER add symptoms, dates, or descriptions that aren't in the source
  • If a day has no entry, mark it as "No entry" — do not infer
  • If a symptom description is unclear, preserve it verbatim rather than interpreting
  • MANDATORY: Before marking any day as "NO ENTRY", check ALL available sources (weekly journal text files, legal documentation, week folders, doctor visit notes, medical records, memory logs)
  • Color scheme: Dark blue (#1E3A5F) for emphasis, headings, and important notes. No red text anywhere. Yellow backgrounds for present symptoms in tables. Grey backgrounds for absent symptoms. Neutral, factual language at all times.

3. Report Structure (CANONICAL FORMAT)

  1. Title Page — R. WARD / INJURY JOURNAL / Contemporaneous Record for Jacobson Law Legal Counsel. Patient details: Robert Ward, Incident 13 May 2026, Times Square NYC, struck by bus. Journal period, last updated date, classification: PRIVILEGED. "ORIGINAL CONTEMPORANEOUS RECORD — VERBATIM ENTRIES PRESERVED". NOTE: Do NOT include Date of Birth on the title page or in the report.
  2. Table of Contents — Numbered section list
  3. Section 1: Executive Summary — Paragraph overview of incident and key findings. Include total medical costs. Neutral MRI language.
  4. Section 2: Physiotherapy Report — Clinical Findings (Rep_RW260526) — Patient details, subjective findings, objective findings, assessment, treatment note.
  5. Section 3: Week 1 — Raw Journal (Days 1-7) — Verbatim entries with day numbers and dates.
  6. Section 4: Week 2 — Raw Journal (Days 8-15) — Same format.
  7. Section 5: Week 3 — Raw Journal (Days 16-24) — Same format.
  8. Section 6: Week 4 — Raw Journal (Days 25-34) — Same format. Add week pattern summary at end.
  9. Section 7: Symptom Progression Timeline — LANDSCAPE orientation. Symptoms across top (columns), dates down side (rows). Standard 12 columns.
  10. Section 8: Medical Care Received — Table with 5 columns: Date, Provider, Type, Findings/Treatment, Cost|Paid|Receipt. Cross-referenced against the Costs & Payments Ledger.
  11. Section 9: Payments & Expenses — Leave blank for spreadsheet image. Add summary line.
  12. Section 10: Key Symptoms for Legal Emphasis — 10 key symptoms with full detail.
  13. Section 11: Red Flag Symptoms — Bullet list of escalating/worsening symptoms.
  14. Section 12: Documentation Checklist — 3-column table: Document, Description, Obtained (YES/PENDING).

4. Symptom Table Design

MANDATORY format: Symptoms across top, dates down side.

Standard columns (in order): Date, Day, Body Pain, Tinnitus, Eye Pain/Pressure, Neck/Cervical, Sleep, Cognitive, Balance/Vestibular, Heart/Palpitations, Numbness/Paresthesia, Functional Capacity.

Cell rules: Use severity scores when provided (e.g., "6/10"). Use "—" for absent symptoms. Keep cell content under 40 characters for PDF fitting. Use footnotes for detail.

5. Output Formats

  • DOCX — Primary format (legal documentation for attorneys)
  • PDF — Final format for filing (generated from DOCX)
  • Build script: scripts/build-injury-journal-v5.py (current version)

All reports generated by pARXYS MUST include:

  2. Title Page Footer: "Generated by pARXYS — parxys.com" in italic medium blue below the source line
  3. Final Section — "About This Document": Full pARXYS branding page with heading, body, tagline, description, link, and closing

6. Verification

  • Every symptom in the table MUST trace to a verbatim quote in the raw journal
  • Every date MUST match the raw journal
  • If a date has no journal entry, mark "No entry provided"
  • Cross-reference medical care log against doctor/physio visit dates in the journal
  • Cross-reference medical care log against the Costs & Payments Ledger
  • Verify PDF renders correctly with table fitting on page (landscape for symptom table)
  • Read the previous report before updating — verify no content was lost

9. Medical Care Log — Cross-Reference Rule (MANDATORY)

The medical care log MUST be cross-referenced against the Costs & Payments Ledger to ensure:

  • All medical visits listed in the ledger appear in the care log
  • All costs are tracked (both $ and EUR)
  • Payment status is recorded (Paid/Not yet)
  • Receipt status is recorded (YES/NO)
  • Bellevue Hospital visits (from NYC) are included

MANDATORY VERIFICATION STEP: Before finalizing ANY version, compare EVERY row in the ledger against the medical care log and vice versa. If any row appears in the ledger but NOT in the document, ADD IT. If any row appears in the document but NOT in the ledger, FLAG IT.
