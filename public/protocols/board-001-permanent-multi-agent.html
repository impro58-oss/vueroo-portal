PROTOCOL-BOARD-001 — Permanent Multi-Agent Board Deployment

Department: BOARD

Version: 1.0

Created: 2026-08-17

Owner: Lumina

Status: ACTIVE

Trigger: Setting up permanent AI board members as isolated OpenClaw agents

Purpose

Deploy synthetic board members as permanent, always-on OpenClaw agents — not ephemeral subagents. Each twin gets its own workspace, session store, Telegram bot, heartbeat, and cron schedule. They communicate via sessions_send and shared context files. This protocol is replicable for any future board expansion.

Prerequisites

  • OpenClaw installed and running (gateway on port 18001)
  • Telegram bot tokens for each twin (created via BotFather)
  • Telegram supergroup with topic channels (one per twin + one for board-wide)
  • agentToAgent messaging enabled in config
  • Shared context files created (BOARD-STATE.md, DECISION-LOG.md, THESIS.md)

Step-by-Step Deployment

Step 1: Create Telegram Bots

For each twin, create a Telegram bot via @BotFather:

/newbot
  Name: Thiel-Twin
  Username: thiel_twin_board_bot
  
/newbot
  Name: Alex-Twin
  Username: alex_twin_board_bot
  
/newbot
  Name: Paul-Twin
  Username: paul_twin_board_bot
  
/newbot
  Name: Pérez-Twin
  Username: perez_twin_board_bot
  
/newbot
  Name: Collison-Twin
  Username: collison_twin_board_bot

Record each bot token. Disable Privacy Mode for each bot if using in groups:

/setprivacy → Disable

Step 2: Create Telegram Supergroup

  1. Create a supergroup: "Avaark Board"
  1. Enable topics: Group Settings → Topics → On
  1. Create topics:
  • "Board Wide" (general)
  • "Thiel — Strategy"
  • "Alex — Growth"
  • "Paul — Cash Protection"
  • "Pérez — Cycle Timing"
  • "Collison — Operations"
  1. Add all 5 twin bots to the supergroup
  1. Record the supergroup chat ID (negative number)
  1. Record each topic ID

Step 3: Create Agent Workspaces

For each twin, create a workspace directory with bootstrap files:

openclaw agents add thiel --workspace ~/.openclaw/workspace-thiel --non-interactive
openclaw agents add alex --workspace ~/.openclaw/workspace-alex --non-interactive
openclaw agents add paul --workspace ~/.openclaw/workspace-paul --non-interactive
openclaw agents add perez --workspace ~/.openclaw/workspace-perez --non-interactive
openclaw agents add collison --workspace ~/.openclaw/workspace-collison --non-interactive

Step 4: Write Each Twin's SOUL.md

Each twin workspace gets a SOUL.md defining their persona, role, layer, operating constraints, and what files to read on startup.

Step 5: Write Each Twin's AGENTS.md

Each twin workspace gets an AGENTS.md with their operating protocol — how they work, what they can do, decision authority, escalation rules.

Step 6: Create Shared Context Files

Create these files in EACH twin workspace (copy or symlink to the master versions in the main workspace):

  • board/BOARD-STATE.md — living state (updated after every interaction)
  • board/DECISION-LOG.md — append-only decision history
  • board/THESIS.md — the Avaark thesis (north star for all agents)

Step 7: Configure openclaw.json

Add to agents.list:

{
  id: "thiel",
  workspace: "~/.openclaw/workspace-thiel",
  model: { primary: "ollama/glm-5.2:cloud", fallbacks: ["ollama/glm-5.1:cloud"] },
  heartbeat: {
    every: "4h",
    prompt: "Read board/BOARD-STATE.md and board/DECISION-LOG.md. Check your layer (L4 Strategy). If nothing needs attention, reply HEARTBEAT_OK.",
    target: "none",
    isolatedSession: true
  },
  identity: { name: "Thiel-Twin", emoji: "♟️" }
}

Repeat for each twin with appropriate model, heartbeat interval, and identity.

Step 8: Enable Agent-to-Agent Communication

{
  tools: {
    agentToAgent: {
      enabled: true,
      allow: ["main", "thiel", "alex", "paul", "perez", "collison"]
    }
  }
}

Step 9: Configure Telegram Bindings

Add each twin's bot token and bind it to the supergroup topics:

{
  channels: {
    telegram: {
      accounts: {
        default: { botToken: "EXISTING_TOKEN" },
        thiel: { botToken: "THIEL_BOT_TOKEN" },
        alex: { botToken: "ALEX_BOT_TOKEN" },
        paul: { botToken: "PAUL_BOT_TOKEN" },
        perez: { botToken: "PEREZ_BOT_TOKEN" },
        collison: { botToken: "COLLISON_BOT_TOKEN" }
      }
    }
  },
  bindings: [
    { agentId: "thiel", match: { channel: "telegram", accountId: "thiel" } },
    { agentId: "alex", match: { channel: "telegram", accountId: "alex" } },
    { agentId: "paul", match: { channel: "telegram", accountId: "paul" } },
    { agentId: "perez", match: { channel: "telegram", accountId: "perez" } },
    { agentId: "collison", match: { channel: "telegram", accountId: "collison" } }
  ]
}

Step 10: Set Up Heartbeats and Cron Schedules

Each twin gets a heartbeat appropriate to their layer:

Twin Heartbeat Purpose
Collison Every 2h Check build status, Snodo health, pending engineering tasks
Alex Every 4h Check growth metrics, outreach pipeline, market signals
Paul Every 6h Check financial signals, tax deadlines, cash position
Pérez Daily 08:00 Cycle timing check, market phase assessment
Thiel Daily 09:00 Strategic watch, competitive landscape, monopoly vector check

Step 11: Verify

openclaw agents list --bindings
openclaw gateway restart

Shared Context File Maintenance

BOARD-STATE.md

  • Updated by: Lumina (main agent) after every board interaction
  • Read by: All twins on startup and heartbeat
  • Purpose: Current state of each member, fuel company, open question, and decision

DECISION-LOG.md

  • Updated by: Lumina (main agent) — append-only, every decision timestamped
  • Read by: All twins on startup and heartbeat
  • Purpose: Complete decision history. If it's not here, it hasn't been decided.

THESIS.md

  • Updated by: Roo (human) only — this is the north star
  • Read by: All twins on startup
  • Purpose: The Avaark mission, fuel strategy, and founding principles

Inter-Agent Communication Protocol

Twins communicate via sessions_send:

sessions_send(agentId="alex", message="HANDOFF\nfrom: collison\nto: alex\ntask_id: snodo-launch\nsummary: Snodo build complete, ready for growth plan\ncontext: platform live at snodo.app, 0 users\ndone_when:\n- 10 builders signed up\n- first paid transaction processed")

Handoff Format (from multi-agent-kit)

HANDOFF
from: <agent-id>
to: <agent-id>
task_id: <unique-id>
priority: P1|P2|P3
summary: <one line>
context: <relevant details>
deliver_to: <telegram chat:topic>
deadline: <asap|date>
done_when:
- <criteria 1>
- <criteria 2>

Escalation Rules

  • Any twin can escalate to Lumina (main) via sessions_send(agentId="main", ...)
  • Paul can block any spending recommendation from any twin
  • Thiel can escalate strategic concerns to Roo via Lumina
  • Twins do NOT communicate directly with Roo — they go through Lumina
