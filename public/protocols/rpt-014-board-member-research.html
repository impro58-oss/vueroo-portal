RPT-014 — Board Member Research and Knowledge Extraction Protocol

Department: RPT (Reports)

Version: 1.1

Created: 2026-08-16

Updated: 2026-08-16 (v1.1 — added Steps 8-11: NotebookLM setup, book downloads, cron reminders, knowledge extraction)

Owner: Lumina

Status: ACTIVE

Trigger: Any time Roo requests research and knowledge extraction for a new board member

Purpose

Define the EXACT process for researching a new board member candidate, gathering all available knowledge resources (YouTube, books, essays, PDFs, lectures), and preparing them for ingestion into NotebookLM and the Lumina brain.

This protocol exists because the first run (Peter Thiel, August 2026) was done ad hoc. Future runs should follow this standard process for consistency and completeness.

THE PROCESS — 11 Steps

Step 1: Web Search for All Content Categories

Run parallel web searches for the person across these categories:

  • "[Name] YouTube playlist lectures talks complete collection"
  • "[Name] books written list all books author"
  • "[Name] Stanford OR Harvard OR university lectures YouTube course"
  • "[Name] essays papers PDF free download"
  • "[Name] YouTube talks interviews playlist [current year]"
  • "[Name] recommended books reading list"

Fire all searches simultaneously for speed. Collect ALL URLs.

Step 2: Identify Existing Compilations

Look for existing curated compilations of the person's work:

  • Startup Archive (startuparchive.org) — often has complete essay + talk lists
  • Goodreads author page — for books written and recommended
  • YouTube channels dedicated to compiling the person's videos
  • University course archives — for lecture notes
  • Personal websites or foundation sites

These compilations save hours of individual URL hunting. Prioritize them over individual search results.

Step 3: Catalog All Resources Found

Organize into these categories:

A. Books — List every book written by the person, with:

  • Title and publication year
  • Co-authors if any
  • PDF availability (check archive.org, academia.edu, PDF repositories)
  • Status: in print, out of print, available as PDF

B. YouTube Playlists — List every existing playlist, with:

  • Playlist URL
  • Estimated video count
  • Theme/focus of the playlist
  • Source (who maintains it)

C. Individual YouTube Videos — List every individual talk, interview, and lecture, organized by year (most recent first), with:

  • Video URL
  • Title
  • Source/channel
  • Date
  • Duration (if known)

Target: 50-100 total videos across all playlists and individual videos.

D. Lecture Notes and Course Materials — For university courses, find:

  • Class-by-class notes (often on Tumblr, blogs, or university sites)
  • Syllabus PDFs
  • Course transcripts
  • Podcast versions (Spotify, Apple Podcasts)

E. Essays and Writings — List every essay, article, and op-ed, with:

  • Title
  • Publication (NYT, WSJ, etc.)
  • Date
  • URL (prefer free/paywall-free versions)

F. Additional Resources —

  • Recommended books BY the person (for understanding their influences)
  • Comprehensive compilation sites (Bishop Rock, Startup Archive, etc.)
  • Podcast appearances (Spotify, Apple, Castbox)
  • Debate appearances

Step 4: Check Local Book Resources

Check Roo's local book resource locations for any books by the person:

  • Search in Roo's PDF library locations
  • Check any book download resources Roo has provided previously
  • If books exist locally, note the file paths
  • If not, note where they can be downloaded (archive.org, PDF repositories)

Step 5: Compile Master Resource File

Write a single text file containing ALL resources, organized by category. Format:

  • Clear section headers with === separators
  • Every URL on its own line with a brief description
  • Books listed with PDF download links
  • Videos numbered sequentially
  • Lecture notes with individual class URLs
  • Essays with publication source and date

File naming: [Person-Name]-Complete-Resource-List.txt

Location: project-bazaar/ (or relevant project folder)

Open in: Notepad++ (NOT Notepad, NOT default editor — always Notepad++)

Step 6: Prepare NotebookLM Strategy

At the end of the resource file, include a recommended NotebookLM strategy:

  • How many notebooks to create (usually 1 per person)
  • What to upload first (books as PDFs, then lecture notes, then essays)
  • Which YouTube URLs to add for transcription
  • Which recommended books to include for context on influences
  • Suggested query topics for extraction

Step 7: Save Protocol Artifacts

Save the following:

  • Master resource list → project folder, open in Notepad++
  • Brain note → vault/90-System/Brain/ (documenting who was researched, when, what was found)
  • Memory file → memory/ (for future reference on the research process)

Step 8: Create NotebookLM Notebooks

Using the nlm CLI tool (already installed and authenticated):

  1. Check authentication: nlm login --check
  1. Create notebook(s): nlm notebook create "[Person Name]" --json
  • If total sources > 50, create a second notebook: nlm notebook create "[Person Name] 2 — Lectures Notes Essays" --json
  • Split: YouTube videos in Notebook 1, lectures/essays/books in Notebook 2
  • Record the notebook_id from each creation response
  1. Add YouTube sources in batches of 25 max:

nlm source add "[notebook-id]" --youtube "URL1" --youtube "URL2" ... --json

  • You can repeat --youtube flags for bulk upload
  • Wait for each batch to complete before starting the next
  • Do NOT mix --youtube and --url flags in the same command (it errors out)
  1. Add essay/lecture URL sources separately:

nlm source add "[notebook-id]" --url "URL1" --url "URL2" ... --json

  • Free/non-paywalled URLs only — NotebookLM cannot access paywalled content
  • For paywalled essays: note them in the resource file for Roo to manually copy text
  1. Add PDF books when Roo downloads them:

nlm source add "[notebook-id]" --file "path/to/book.pdf" --wait

  • The --wait flag waits for processing to complete
  • PDFs go into whichever notebook has the lectures/essays (Notebook 2)
  1. Verify source count: nlm source list "[notebook-id]"
  • Target: 50+ sources per notebook, 100+ total across both

NotebookLM limitations discovered during Peter Thiel run (v1.1 — verified):

  • Cannot mix --youtube and --url in same command — must run separately
  • Paywalled content (FT, NYT, WSJ, Wired, National Review) cannot be added as URL sources
  • Some Tumblr/blog URLs work (Blake Masters CS183 notes worked)
  • Processing time: 25 YouTube videos takes ~60-90 seconds
  • NotebookLM has a source limit per notebook (~50 is safe, 100 may hit limits)
  • PDF uploads via nlm CLI DO NOT WORK — API returns INVALID_ARGUMENT for local file paths
  • Direct PDF URLs do NOT WORK either — archive.org and icrrd.com PDF links both rejected
  • OceanofPDF.com is behind Cloudflare — cannot be accessed programmatically, must open in Chrome
  • Archive.org detail page URLs — rejected as sources, need direct PDF download link
  • YouTube URLs are the most reliable source type — work consistently in batches of 25
  • Expect a 5-10% YouTube failure rate — some videos are age-restricted, removed, private, or region-locked. These will show as status 3 (failed) in NotebookLM. Delete them and move on — they cannot be fixed
  • Paywalled essay URLs will fail — FT, NYT, WSJ, Wired, First Things, National Review all failed. For these, Roo must copy the text manually from the article and Lumina adds it as a text source via nlm source add [notebook-id] --text "[article text]" --title "[essay title]"
  • Tumblr blog URLs work — Blake Masters CS183 lecture notes on Tumblr all processed successfully
  • Solution for PDFs: Roo uploads manually via NotebookLM web interface (drag and drop)
  • Source status codes: status 2 = processed/working, status 3 = failed. Check with nlm source list [notebook-id] --json and delete failures with nlm source delete [source-id] --confirm

Step 9: Book Download Assistance

  1. Check OceanofPDF.com — open search in Chrome: https://oceanofpdf.com/?s=[Person+Name]
  • OceanofPDF is behind Cloudflare so cannot be fetched programmatically — must open in browser
  • Roo searches and downloads manually from this tab
  1. Check Archive.org — https://archive.org/details/[book-title]
  • Archive.org can be fetched and direct download links can be opened in Chrome
  1. Download PDFs programmatically when direct links are available:
    2.    $outputPath = "$env:USERPROFILE\Downloads\[Book-Title].pdf"
   Invoke-WebRequest -Uri "[direct-pdf-url]" -OutFile $outputPath -TimeoutSec 120 -UseBasicParsing
  1. Move to reading folder and clean up filename:
    2.    Move-Item "$env:USERPROFILE\Downloads\[raw-filename]" "C:\Users\impro\Documents\reading\[Clean-Book-Title].pdf" -Force
  1. Open all download tabs in Chrome so Roo can click and download manually for OceanofPDF:

Start-Process chrome.exe -ArgumentList "url1","url2","url3"

  1. Upload PDFs to NotebookLM MANUALLY — the nlm CLI cannot upload PDF files. Roo must:
  • Open the NotebookLM notebook in Chrome
  • Drag and drop the PDF file into the notebook
  • Wait for processing to complete
  • The PDF will then be queryable alongside the YouTube and essay sources
  1. Books go to BOTH NotebookLM AND the brain:
  • NotebookLM: Roo uploads PDF manually via web interface (drag and drop)
  • Brain: Lumina reads the PDF directly using the read tool and builds persona + knowledge base
  • If PDF is too large for read tool (>50KB), read in sections using offset/limit parameters

Step 10: Set Knowledge Extraction Reminders (Cron)

After all sources are loaded into NotebookLM, set up automated reminders to query NotebookLM and extract knowledge into the brain.

  1. Set a cron job for 24 hours after loading — gives NotebookLM time to process all sources:
  • Schedule: 0 0 * (midnight, 24 hours after load)
  • Task: Query NotebookLM with extraction questions (see Step 11)
  • The cron sends a Telegram message to Roo reminding him that NotebookLM is ready for extraction
  1. Extraction query schedule — run queries in this order:
  • Day 1 after load: Core frameworks and mental models
  • Day 2: Decision-making patterns and voice/style
  • Day 3: Specific applications to Roo's portfolio
  • Day 4: Cross-referencing and synthesis
  1. Cron command format:

Use the OpenClaw cron system to schedule reminders:

   openclaw cron add --name "[Person] NotebookLM Extraction Reminder" 
     --schedule "0 18 * * *" 
     --message "NotebookLM sources for [Person] should be processed. Run extraction queries now using nlm notebook query."
     --target telegram:1018254667
  1. Set 4 daily reminders (one per extraction day) with decreasing frequency:
  • Day 1: Full extraction — core frameworks
  • Day 2: Voice and decision patterns
  • Day 3: Portfolio applications
  • Day 4: Synthesis and cross-reference
  • After Day 4: Weekly check-in to see if Roo has new questions

Step 11: Knowledge Extraction and Brain Building

Once NotebookLM has processed all sources, run structured queries to extract knowledge:

  1. Run NotebookLM queries via nlm CLI:
    2.    nlm notebook query "[notebook-id]" "What are [Person]'s core frameworks and mental models?"
   nlm notebook query "[notebook-id]" "How does [Person] make decisions? What patterns do they follow?"
   nlm notebook query "[notebook-id]" "What is [Person]'s voice and communication style?"
   nlm notebook query "[notebook-id]" "How would [Person] evaluate these specific companies: [list Roo's portfolio]?"
   nlm notebook query "[notebook-id]" "What questions would [Person] ask that other board members wouldn't?"
  1. Build persona file from extraction results:
  • File: memory/[person-name]-persona.md
  • Include: voice map, signature phrases, how they think, what they'd never say, decision frameworks, cross-references to other board members
  • Follow the same format as alex-hormozi-persona.md
  1. Build knowledge base from extraction results:
  • File: memory/[person-name]-knowledge-base.md
  • Include: all core frameworks with formulas, specific examples, applications, cross-references
  • Target 25-30KB (similar to Alex Hormozi KB at 27.9KB)
  • Follow the same structure as alex-hormozi-knowledge-base.md
  1. Build mind map (RPT-012 format):
  • File: mind-maps/[Person-Name]-Board-Member-Knowledge-Map.txt
  • 3+ levels deep, indentation-based hierarchy
  • Include: core identity, frameworks, what they bring, what they don't bring, cross-references
  1. Save brain note to vault:
  • File: vault/90-System/Brain/strategy/[date]-[Person-Name]-Board-Member-Build.md
  • Document: who they are, why they were selected, what frameworks they bring, how they complement the board
  1. Save memory file:
  • File: memory/[person-name]-board-member-research-[date].md
  • Document: research process, sources loaded, extraction results, files created
  1. Spawn board member as persistent agent:
  • Use the persona and knowledge base files
  • Label: "[Person Name] Board Member"
  • Make available for pinning in the UI
  • Introduce to existing board members via their knowledge maps

QUALITY BAR

  • Minimum video count: 50 videos (individual + playlist). Target 100+.
  • All books by the person must be listed — no omissions
  • All essays must have working URLs — verify before listing
  • PDF links must be to free sources — don't list paywalled PDFs
  • Lecture notes must be complete — all classes in a course, not just a few
  • File must be openable in Notepad++ without formatting issues

COMMON MISTAKES TO AVOID

  • Listing paywalled content without a free alternative
  • Missing the person's early or less-known work (pre-fame)
  • Not checking for existing compilations (wastes time on individual URLs)
  • Forgetting to check for course lecture notes separately from YouTube videos
  • Not including the person's recommended books (critical for understanding their influences)
  • Using Notepad instead of Notepad++ to open the file (Roo's preference)
  • Putting the file in the workspace root instead of the project folder
