← Back to Protocol Dashboard ﻿# RPT-002 Trading Analysis Report Protocol

Department: RPT (Reporting) Version: 1.0 Created: 2026-05-25 Owner: Lumina Status: ACTIVE

Purpose

Analyze and report on trading system performance with proper metrics, before/after comparisons, and actionable insights. No declaration without measurement.

Trigger

  • After any trading system parameter change
  • Weekly or monthly performance review
  • When Roo asks "how is the trading doing?"
  • After a significant drawdown or winning streak

    • Prerequisites

  • Trading data available in data/paper_trading/
  • Performance data loaded and analyzed

    • Steps

    Step 1: Load Data

    python
import json
with open('data/paper_trading/trades_v52.json') as f:
    trades = json.load(f)
with open('data/paper_trading/positions_v52.json') as f:
    positions = json.load(f)

    Step 2: Calculate Core Metrics

    Required metrics for every report:

    | Metric | Formula | Why It Matters | |--------|---------|---------------| | Total P&L | Sum of all trade pnl | Bottom line | | Win Rate | Wins / Total Trades | Reliability | | Avg Win | Mean of winning trades | Upside potential | | Avg Loss | Mean of losing trades | Downside risk | | Profit Factor | Gross Wins / Gross Losses | Edge strength (>1.5 is good) | | Max Drawdown | Peak-to-trough decline | Worst case | | Expectancy | Total P&L / Total Trades | Per-trade edge | | Sharpe Ratio | (Mean Return - Risk Free) / Std Dev | Risk-adjusted returns |

    Step 3: Segment Analysis

    Break down performance by:
  • Direction (LONG vs SHORT): Which works better?
  • Exit reason (DONCHIAN, TIME_STOP, ATR_STOP, TRAILING_STOP): Which exits are effective?
  • Holding period (1 bar, 2-3 bars, 4-7 bars, 8+): Optimal holding time?
  • Symbol (BTC, ETH, etc.): Any token-specific patterns?
  • BTC regime (bullish/bearish): Performance in different market conditions?

    • Step 4: Before/After Comparison

    When reporting on a parameter change (like V5.1 → V5.2): 
    
| Metric | V5.1 (Before) | V5.2 (After) | Change |
|--------|---------------|-------------|--------|
| Win Rate | 16% | [new]% | [delta] |
| Profit Factor | 0.46 | [new] | [delta] |
| Max Drawdown | -€482 | [new] | [delta] |
    Hard rule: Every parameter change MUST have before AND after scores. No exceptions.

    Step 5: Identify Patterns

  • What's working? (winning trades cluster by what attribute?)
  • What's failing? (losing trades cluster by what attribute?)
  • Is the system improving or degrading over time?
  • Are there any systematic biases (always losing on shorts? specific tokens?)

    • Quality Gates

    All core metrics calculated
    Segment analysis completed
    Before/after comparison included (if parameter change)
    No declaration without measurement
    Dashboard updated and verified

    Error Handling

    | Error | Response | |-------|----------| | Not enough trades for analysis | Report "insufficient data" — do NOT draw conclusions from <10 trades | | NaN in calculations | Check data pipeline, sanitize, re-run | | Conflicting metrics (high P&L but low win rate) | Present both, let Roo decide |
