CDP-001 Browser CDP Course Extraction

Department: CDP (Browser Automation) Status: NEW

Protocol: Browser CDP Course Extraction

Version: 1.0

Date: 2026-08-15

Author: Lumina

Applies to: Extracting video/text/PDF content from locked membership sites (Kajabi, Teachable, Thinkific, etc.) when openclaw CLI and bundled browser agents are non-functional.

When to Use This Protocol

Use this protocol when:

  • openclaw CLI hangs or fails on all commands
  • agent-browser bundled Chrome fails with side-by-side configuration errors (os error 14001)
  • The target site requires a logged-in session
  • Standard openclaw browser or MCP tools cannot access the content

Required Setup

  1. Google Chrome installed on the host machine
  1. Chrome launched with remote debugging enabled:
    2.    # Kill existing Chrome processes first if needed
   Get-Process chrome | Stop-Process -Force

   # Launch Chrome with remote debugging
   & "C:\Program Files\Google\Chrome\Application\chrome.exe" `
     --remote-debugging-port=9222 `
     --user-data-dir="C:\Users\YOUR_USER\ChromeDebug" `
     https://member.askaboutwealth.ie/products/mastering-your-finances
  1. User logged in manually to the target site in the remote-debugging Chrome window
  1. CDP endpoint accessible: http://127.0.0.1:9222

Tools Used

  • Playwright via connect_over_cdp()
  • Direct Wistia embed page fetching via urllib
  • ffmpeg for video download and audio extraction
  • Python scripts for orchestration

Step-by-Step Procedure

Step 1: Verify CDP Connection

from playwright.sync_api import sync_playwright

with sync_playwright() as p:
    browser = p.chromium.connect_over_cdp("http://127.0.0.1:9222")
    print(browser.contexts[0].pages[0].url)

Step 2: Extract Lesson Links from Course Page

Navigate to the course page and collect all lesson links.

Key selectors:

  • a[href*="/posts/"] for Kajabi
  • Expand collapsed sections if necessary by clicking expanders/accordions
  • Scroll to bottom to load lazy content

Step 3: Extract Content Per Lesson

For each lesson page:

  1. Navigate via the existing logged-in page
  1. Wait for networkidle
  1. Extract lesson text to markdown
  1. Extract PDF links
  1. Extract Wistia video IDs from:
  • /medias/<id>
  • wistia.com/embed/medias/<id>
  • wistia.net/embed/iframe/<id>
  • data-wistia-id="<id>"
  • iframe src attributes containing /embed/<id>

Step 4: Get Direct MP4 URLs from Wistia

For each Wistia ID:

  1. Fetch: https://fast.wistia.net/embed/iframe/{wistia_id}
  1. Parse W.iframeInit({...}, {}); JSON
  1. Select best MP4 asset:
  • Prefer display_name of 720p or 1080p
  • Otherwise highest bitrate
  1. The .bin URL returned is a direct MP4 download

Step 5: Download Audio

Use ffmpeg to download the MP4 and extract audio:

ffmpeg -headers "Referer: https://member.askaboutwealth.ie/" \
  -i "https://embed-ssl.wistia.com/deliveries/HASH.bin" \
  -vn -c:a libmp3lame -q:a 4 \
  -y output.mp3

Step 6: Naming Convention

Use module/lesson numbering:

Module_01_Lesson_01_-_Lesson_Title.mp3
Module_01_Lesson_02_-_Lesson_Title.mp3

Step 7: Rate Limiting

  • Add 10-15 second delays between downloads
  • Do not run multiple extraction scripts simultaneously
  • Avoid parallel downloads from the same site
  • Monitor for blocks or CAPTCHAs

Key Lessons Learned

  1. Do not rely on openclaw browser or bundled Chrome when they fail — use system Chrome via CDP.
  1. Wistia .m3u8 URLs may be incomplete — direct MP4 .bin URLs from the embed page are more reliable.
  1. Course page menus may not show all modules — some modules may be locked, hidden, or in separate products.
  1. Always verify the actual number of extractable lessons against the user's expectation; sales pages may list modules not yet accessible in the member area.
  1. Keep module/lesson numbering consistent to align audio with course structure.
