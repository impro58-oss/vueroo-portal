Purpose

Find online business opportunities that are proven to have demand, not yet well-served by competitors, buildable for under $2K, can run autonomously by AI, and could attract a community/marketplace dynamic. Uses Mythos Engine deep-work runtime for multi-cycle research with uncertainty tracking and claims verification.

Why This Exists

Previous reactive approach (scan marketplaces → find proven products → check if we can do better → find competitors → scrap) consistently found filled gaps because it looks where 100K+ indie hackers look. This protocol reframes the search to start from emerging behaviours, not existing products.

The Reframe

Old Approach New Approach
Marketplace → Product → Competitor → Scrap Trend → Behaviour → Need → Product
Start from what exists Start from what's emerging
Reactive (find a gap in a crowded market) Proactive (find a gap that doesn't have a market yet)
Look where everyone looks Look where nobody is looking yet
"Can we build a better X?" "What new behaviour needs a tool that doesn't exist?"

Search Vectors (Where to Look)

1. New Technology → New Behaviour → New Need

Technology changes create behaviours that didn't exist before:

  • AI created new needs: AI content detection, prompt ownership, AI hallucination tracking, AI content licensing
  • Platform API changes: new APIs create new possibilities (Bluesky, Telegram bots, Threads)
  • Regulatory changes: new laws create new compliance needs
  • Hardware shifts: AR/VR, wearables, IoT creating new interaction patterns

2. Emerging Communities → Underserved Tooling

Niche communities forming around new interests:

  • Trading cards / TCG (Pokemon, One Piece, Lorcana, Gundam)
  • Niche collecting (vintage tech, mechanical keyboards, sneakers, plants)
  • New hobbies trending on TikTok/YouTube (bookbinding, aquascaping, urban sketching)
  • Discord communities around new interests
  • Reddit subreddits that grew 500%+ in 2025-2026

3. AI-Created Needs

Needs that AI itself made necessary:

  • AI content detection / human verification
  • AI asset marketplaces (agents, workflows, prompts, kits)
  • AI hallucination tracking for brands
  • AI content licensing and attribution
  • Prompt ownership and provenance

4. Quirky / Unexpected Trends

Social scenes building around things nobody expected:

  • New game/collectible trends going viral
  • Niche sports/activities gaining community
  • Cultural phenomena creating micro-economies

Roo's Constraints (Filter)

Every candidate must pass ALL of these:

  1. ✅ Proven demand — evidence people want/need this
  1. ✅ Not well-served — no good competitor exists OR competitors have exploitable weaknesses
  1. ✅ Buildable under $2K — actual cost to launch
  1. ✅ Autonomous — AI runs it, not human labour
  1. ✅ Not B2B service provider — not consulting, not agency work
  1. ✅ Community/marketplace dynamic — brings people together
  1. ✅ Sellable asset — can be offloaded on TrustMRR/Acquire later
  1. ✅ Name available — domain and social handles not taken
  1. ✅ Competitor-checked — full review search done before presenting

Mythos Engine Run Structure

Cycle Action Output
1 Reframe search methodology — stop looking where everyone looks New search approach documented
2 Scan emerging behaviours, new tech needs, underserved communities across all search vectors List of 10-15 raw candidates
3 For each candidate: competitor search, name availability check, gap verification Filtered list with evidence
4 Apply Roo's constraints filter — only those passing ALL 9 criteria survive Final 3-6 opportunities
5 Write opportunity discovery report with claims ledger and sources Deliverable report

Competitor Check Protocol (Per Candidate)

Before presenting ANY idea to Roo, check:

  1. Direct competitors — web search for the exact product type
  1. Name availability — domain check (.com, .io, .ai), social handles, GitHub
  1. Existing product — does a live website exist? Is it actually built or just parked?
  1. Review quality — if competitors exist, check Trustpilot, Reddit, G2 for complaints
  1. Gap assessment — is the gap real or filled? What specific weakness can we exploit?

Rule: If a competitor exists AND serves the gap well → SCRAP. If a competitor exists but has exploitable weaknesses → KEEP with notes.

Validation Checklist

  • [ ] Demand proven (evidence cited)
  • [ ] Competitor check completed (all found competitors listed)
  • [ ] Name checked (domain + social)
  • [ ] Gap verified (real or filled — evidence provided)
  • [ ] Build cost estimated
  • [ ] Revenue model outlined
  • [ ] Claims ledger in report (every claim has source + confidence)
  • [ ] Sources cited (URLs listed)
