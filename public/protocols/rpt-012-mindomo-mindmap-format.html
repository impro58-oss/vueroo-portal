RPT-012 — Mindomo Mind Map Text Format Protocol

Department: RPT (Reports)

Version: 1.0

Created: 2026-08-15

Owner: Lumina

Status: ACTIVE

Trigger: Any time Roo requests a mind map file for Mindomo, or a navigable knowledge structure

Purpose

Define the EXACT text format for files that Roo uploads to Mindomo (mind map tool). This protocol exists because the format was done incorrectly before (hashtag/dash-based) and Roo had to correct it. The correct format is indentation-based, matching the VOC Question Database file Roo provided as the reference.

THE FORMAT — Indentation-Based Hierarchy

NO hashtags. NO dashes. NO asterisks. NO plus signs. NO commas. NO ampersands. NO bullet junk.

Hierarchy is shown purely by leading spaces (indentation).

Level Indentation Example
Main topic (root) 0 spaces Paul Overy Irish Wealth and Tax Knowledge
Subtopic (level 1) 1 space Core Philosophy and Framework
Sub-subtopic (level 2) 2 spaces Financial Freedom Number
Deeper (level 3+) 3+ spaces Question or detail text

RULES

  1. Main topic = the root node. Plain text, no marker, at the left margin (0 spaces).
  1. Subtopics = indented by 1 space per level. Level 1 = 1 space, Level 2 = 2 spaces, etc.
  1. No punctuation junk: Do NOT use dashes, commas, ampersands, hashtags, asterisks, or plus signs as markers. Write clean text.
  1. Keep topic labels short and clean — a topic is a node label, not a sentence.
  1. Blank lines separate major branches (optional, for readability — Mindomo ignores them).
  1. File extension: .txt (Mindomo Import → Plain Text, or upload the .txt file).
  1. Encoding: UTF-8.
  1. Filename: Use NO spaces in the filename (e.g. Paul-Overy-Knowledge-Mindmap.txt). Spaces get URL-encoded as %20 when the file is opened/downloaded, which corrupts the name. Underscores or hyphens are safe.

MINIMUM DEPTH EXPECTATION (DEFAULT)

A mind map is NOT acceptable with only bare headings. The default minimum is THREE levels of depth:

Level Indentation Content
Main topic 0 spaces The overall subject (root node)
Module 1 space The major category (e.g. Pensions)
Subtopic 2 spaces The specific topic (e.g. Why Pensions Win)
Guidance 3 spaces A short note on what it means + an "Ask Paul" question

Every subtopic MUST have a guidance line beneath it (level 3) that:

  1. States in one line what the topic means / the key fact.
  1. Includes an "Ask Paul: ..." prompt so Roo has a ready question to develop.

This is the approved format (2026-08-15). Bare two-level maps are rejected.

WORKFLOW

  1. Roo requests a mind map for a knowledge domain.
  1. Identify the main topic (root node) — the overall subject.
  1. Identify the main branches (level 1 subtopics) — the major categories.
  1. Identify the sub-branches (level 2+) — the specific topics under each category.
  1. Write the file with indentation showing hierarchy. NO markers.
  1. Save to the relevant memory/ folder.
  1. Open the folder for Roo so they can upload the file to Mindomo.
  1. VERIFY: Read the file back and confirm the indentation hierarchy is correct before declaring done.

COMMON MISTAKES TO AVOID

  • ❌ Using # hashtags (Mindomo's Markdown import uses these, but Roo's preferred format is indentation)
  • ❌ Using - dashes or * asterisks as bullet markers
  • ❌ Using commas or ampersands in topic labels
  • ❌ Putting long sentences as topic labels (keep them short)
  • ❌ Mixing formats (indentation + markers) — pick indentation ONLY
