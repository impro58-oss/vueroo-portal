RSC-002 MedTech Literature Review Protocol

Department: RSC (Research) Version: 1.0 Created: 2026-05-25 Owner: Lumina Status: DRAFT

Purpose

Find, extract, validate, and synthesize medical journal articles and clinical data for MedTech intelligence reports. Every fact must be tagged as VERIFIED or ESTIMATE. No fabrication of clinical data.

Trigger

  • When researching a MedTech topic (device, therapy, clinical outcome)
  • When preparing a competitive intelligence brief
  • When writing a white paper that references clinical evidence
  • When updating NeuroVue data

    • Prerequisites

  • Research question clearly defined (e.g., "What is the recurrence rate for aneurysms treated with Pipeline embolization?")
  • Access to PubMed, Google Scholar, or journal databases
  • PACK Operation available for Perplexity deep research

    • Steps

    Step 1: Define Search Parameters

  • Write the clinical question in PICO format:
    • - Population: Who are the patients? - Intervention: What device/therapy? - Comparison: Compared to what? - Outcome: What outcome measure?
  • Define date range (prefer last 5 years, note if older)
  • Define study types accepted (RCT > meta-analysis > cohort > case series > case report)

    • Step 2: Search Literature

    Primary sources (in order of reliability): 1. PubMed — web_fetch on https://pubmed.ncbi.nlm.nih.gov/?term=[PICO+terms] 2. Google Scholar — web_search with site:scholar.google.com [topic] 3. Perplexity Deep Research (via Roo) — "Find all published clinical studies on [PICO]. Include journal name, year, sample size, and key findings." 4. Cochrane Library — web_search with site:cochranelibrary.com [topic] 5. FDA databases — For device-specific data, search FDA 510(k) and PMA databases

    For each result found:

  • Record: Title, Authors, Journal, Year, DOI/URL
  • Record: Study type, Sample size, Follow-up duration
  • Record: Key finding (exact numbers, not paraphrased)

    • Step 3: Extract and Validate

    For EACH paper selected for inclusion:

    1. Fetch the full text (via web_fetch on DOI or PubMed Central) 2. Extract key data points: - Patient demographics (N=, age range, conditions) - Primary endpoint results (with confidence intervals if available) - Adverse events / complications - Study limitations acknowledged by authors 3. Validate claims: - Cross-reference statistics against abstract numbers - Check if findings are replicated in other studies - Note industry funding or author conflicts of interest

    Step 4: Tag Everything

    CRITICAL RULE: Every data point gets a tag.

    | Tag | When to Use | Example | |-----|-------------|---------| | [VERIFIED] | Confirmed in peer-reviewed publication, numbers match | "Recurrence rate 5.2% at 3 years [VERIFIED: Mocco et al., J Neurosurg 2024]" | | [ESTIMATE] | Inferred, not directly stated, or from non-peer-reviewed source | "Market size ~$2.1B [ESTIMATE: derived from 3 company revenues]" | | [UNVERIFIED] | Claimed but cannot confirm from available sources | "Pipeline Flex 3-year durability rate 95% [UNVERIFIED: company website, no published data]" | | [0.1 MARKER] | No verified data available, using 0.1 as placeholder | "Complication rate [0.1 MARKER: no published data found]" |

    Hard rule from HEARTBEAT.md: No verified data → use 0.1 as marker. NEVER estimate financial data.

    Step 5: Synthesize

    Write the review using this structure:

    markdown

    Literature Review: [Topic]
    Date: YYYY-MM-DD

Studies Found: [N]
Studies Included: [N with inclusion reason]

    Summary of Evidence
    
[2-3 paragraph synthesis of what the evidence shows]
    Study Details

| [Author] | [Year] | [RCT/Cohort/etc] | [N] | [key finding] | [HIGH/MED/LOW] | [VERIFIED/ESTIMATE/UNVERIFIED] |
    Key Findings
    

    — [tag] — Source: [attribution]
    

    — [tag] — Source: [attribution]
    Gaps in Evidence
    

  • [what we don't know]
    • Recommendations for NeuroVue

    Step 6: Update NeuroVue Data

    If findings affect NeuroVue competitive intelligence: 1. Update medtech-intelligence/dashboard/data/ JSON files 2. Add source attribution to each data point 3. Push to GitHub: rooquest1 repo 4. Verify live dashboard reflects changes

    Quality Gates

    Every numerical claim has a source
    Every claim has a VERIFIED/ESTIMATE/UNVERIFIED/0.1 tag
    No financial data estimated (use 0.1 marker)
    At least 3 sources consulted for any clinical claim
    Study limitations acknowledged
    Conflicts of interest noted

    Error Handling

    | Error | Response | |-------|----------| | Full text paywalled | Use abstract data only, tag as [UNVERIFIED] for any claim not in abstract | | Contradictory studies | Present both, note sample sizes, do NOT pick a winner | | No published data found | Use [0.1 MARKER], report gap to Roo | | Company claim without published evidence | Tag [UNVERIFIED], note company source, do NOT present as fact |
