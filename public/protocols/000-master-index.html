Protocol System — Master Index

Created: 2026-05-25 Purpose: Standardized operating procedures for all Lumina operations. No shortcuts. No ambiguity. Same work = same way = fewer errors.

Structure:

  • protocols/ directory contains all individual protocol files

  • Protocols are cross-referenced, not duplicated
  • When in doubt, follow the protocol. When protocol is wrong, update the protocol THEN follow it.

    End-to-End Process Flows

    Flow 1: Research → Intelligence Report

    Idea/Question → RSC-001/007 (Multi-Source Research + AI Interrogation) → RSC-002 (Lit Review) → ⬡ Quality Gate (Verified? Tagged?) → RPT-001 (Write Report) → ⬡ Three Gates (Accuracy, Logic, Utility) → Deliver

    Flow 2: Agent Build → Deploy

    Requirements (DEV-001 S1) → Architecture (DSN-003) → Security Audit (DEV-006) → Implementation (DEV-001 S4) → ⬡ Quality Gates (DEV-002) → Cron + Deploy (DEV-003, DSN-002) → Live + Monitor (OPS-001)

    Flow 3: Book → Knowledge Base

    PDF/EPUB → Full Extraction (RSC-005 S2) → Classify + Tag (RSC-005 S4) → File in Vault (RSC-005 S5) → Synthesize (RSC-005 S7) → Clean Up (RSC-005 S6) → Knowledge Base

    Flow 4: Idea → Project

    Spark (STR-003 S1) → 0→1/1→n (STR-003 S2) → 7 Questions (STR-003 S3) → Resonance Check (STR-003 S4) → Lean Validate (STR-003 S5) → ⬡ Decide (Persevere/Pivot/Perish) → Build (DEV-001)

    Flow 5: Incident → Resolution

    🔴 Incident (OPS-002 S1) → Diagnose (OPS-002 S2) → Classify (OPS-002 S3) → Fix (OPS-002 S4) → ⬡ Verify (OPS-002 S5) → Document (OPS-002 S6) → 🟢 Prevention (OPS-002 S7)

    ---

    Cross-Cutting Rules (Apply to ALL Protocols)

    1. No fabrication. UNKNOWN > wrong. ESTIMATE > unverified. 2. No declaration without measurement. "It works" = live URL + before/after scores. 3. Multi-model verification. HIGH-stakes deliverables get a second model review. 4. Protocol before memory. If memory says one thing and protocol says another, follow the protocol and flag the conflict. 5. Update before override. If the protocol is wrong, update it first, then follow the updated version. 6. Document deviation. If you deviate from a protocol, document WHY in the output.

    ---

    Agent Compliance

    Every agent built under this system MUST: 1. Know which protocols apply to its operations 2. Follow those protocols on every execution 3. Report protocol violations in its output 4. Never shortcut a quality gate
