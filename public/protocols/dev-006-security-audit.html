DEV-006 Security Audit Protocol (Lethal Trifecta)

Department: DEV (Development) Version: 1.0 Created: 2026-05-25 Owner: Lumina Status: DRAFT

Purpose

Audit every agent and system for the Lethal Trifecta vulnerability: when an agent has access to private data, processes untrusted content, AND can make external calls. This is the #1 security risk for AI agents (from Patterns for Building AI Agents, Bhagwat/Gienow).

Trigger

  • Before deploying any new agent (part of DEV-001 Step 3)
  • Quarterly security review of all active agents
  • When a security concern is raised

    • Prerequisites

  • List of all active agents (from AGENTS.md)
  • Understanding of each agent's data flows, inputs, and outputs

    • Steps

    Step 1: Identify the Trifecta for Each Agent

    For each agent, answer these three questions:

    | Question | YES means... | |----------|--------------| | Q1: Does it access private data? | API keys, user data, financial data, vault contents, personal information | | Q2: Does it process untrusted content? | Web-scraped data, user input, external API responses, AI-generated text | | Q3: Does it make external calls? | HTTP requests, API calls, sending messages, writing files outside sandbox |

    Step 2: Classify Risk Level

    | Trifecta Score | Risk Level | Required Safeguards | |---------------|------------|---------------------| | 0 YES | LOW | Standard error handling | | 1 YES | LOW | Standard error handling + input validation | | 2 YES | MEDIUM | Input validation + output filtering + logging | | 3 YES (all three) | HIGH | All safeguards below |

    Step 3: Apply Required Safeguards by Risk Level

    HIGH (3/3 trifecta) — ALL of these: 1. Sandboxed execution — Agent runs in isolated environment 2. Input validation and sanitization — Strip prompt injections, validate schemas 3. Rate limiting — Cap external calls per minute 4. Output filtering — Scan outputs for leaked private data before publishing 5. Human approval for HIGH-impact actions — Financial transactions, external messages, deletions 6. Comprehensive logging — Every input, output, and external call logged 7. Guardrails — Content policy checks on inputs and outputs 8. Principle of least privilege — Agent only has access to what it needs

    MEDIUM (2/3) — Items 2-6 above

    LOW (0-1/3) — Items 2, 6 above

    Step 5: Fix Critical Issues

    Any HIGH-risk agent without proper safeguards MUST be remediated before continuing operation: 1. Add missing safeguards immediately 2. Add HITL approval for HIGH-impact actions 3. Test the safeguards 4. Re-audit after fixes

    Quality Gates

    Every active agent has a trifecta assessment
    Risk level assigned (LOW/MEDIUM/HIGH)
    Safeguards match risk level
    No HIGH-risk agents operating without proper safeguards
    Audit documented in security/ directory
