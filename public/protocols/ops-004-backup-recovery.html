← Back to Protocol Dashboard ﻿# OPS-004 Backup & Recovery Protocol

Department: OPS (Operations) Version: 1.0 Created: 2026-05-25 Owner: Lumina Status: ACTIVE

Purpose

Ensure all critical data and configurations are backed up and recoverable.

Trigger

  • Daily automated (Lumina Drive nightly 22:00 IST)
  • Before any major change (system upgrade, migration, refactoring)
  • After any data loss incident

    • Steps

    Step 1: Identify Critical Assets

    | Asset | Location | Backup Method | Frequency | |-------|----------|---------------|-----------| | Obsidian Vault | C:\Users\impro\Documents\quest vault | OneDrive + Mega DR | Continuous | | Workspace | C:\Users\impro\.openclaw\workspace | Git (rooquest1) | Per commit | | Vueroo Portal | vueroo-portal/ | Git (vueroo-portal) | Per commit | | API Keys | C:\Users\impro\Documents\RooQuest Data\API's\ | Local only | Manual | | Memory | workspace/memory/ | Git + Obsidian sync | Per commit | | Protocols | workspace/protocols/ | Git | Per commit | | Cron Configs | OpenClaw gateway | Not backed up (recreate from docs) | N/A | | Dashboard Data | workspace/data/ | Git (rooquest1) | Per commit |

    Step 2: Verify Backups

    Check each backup location: 1. OneDrive: Obsidian vault synced within last 24h 2. Mega DR: Secondary archive synced within last 48h 3. GitHub rooquest1: Latest push within last 24h 4. GitHub vueroo-portal: Latest push within last 24h

    Step 3: Recovery Procedure

    For each asset type, know how to recover:
  • Obsidian Vault: Restore from OneDrive or Mega
  • Workspace: git clone from rooquest1
  • Vueroo Portal: git clone from vueroo-portal repo
  • API Keys: Re-obtain from providers (last resort)
  • Memory/Protocols: Restore from git history
  • Cron Jobs: Recreate from HEARTBEAT.md documentation

    • Step 4: Test Recovery

    Quarterly (or after major changes): 1. Pick a random backup 2. Restore to a test location 3. Verify the restored data is complete and usable 4. Document any issues found

    Quality Gates

    All critical assets identified
    Backup locations verified
    Recovery procedures documented
    Recovery tested quarterly
