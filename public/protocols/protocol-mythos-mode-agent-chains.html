Mythos-Mode: Multi-Day Agent Protocol

Chaining subagent runs across cron cycles to simulate multi-day autonomous work

What This Is

A system for chaining subagent runs across cron cycles to simulate multi-day autonomous work. Inspired by Fable 5's ability to run agents for days unattended using file-based memory.

How It Works

Cycle 1:
  Cron triggers → Spawn DeepSeek-V4-Pro subagent
  Subagent reads checkpoint_001.md → does work → writes checkpoint_002.md → exits

Cycle 2:
  Cron triggers → Spawn DeepSeek-V4-Pro subagent
  Subagent reads checkpoint_002.md → continues work → writes checkpoint_003.md → exits

Cycle N:
  Continues until task is marked COMPLETE in checkpoint
  Or: Lumina reviews checkpoints and decides to stop

Each cycle is a fresh subagent session with 1M context. The checkpoint file is the persistent memory between cycles.

Checkpoint Format

# Agent Checkpoint — [TASK_NAME]

**Checkpoint #:** N
**Task:** [description of the overall task]
**Phase:** [research/analysis/synthesis/review/complete]
**Status:** [in-progress/complete/blocked]
**Previous checkpoint:** checkpoint_N-1.md (or "none" for first)
**Next action:** [what the next cycle should do]
**Context used:** ~X% (estimate)

## Work Completed This Cycle
[Detailed description of what was accomplished]

## Key Findings
[Bullet points of findings]

## Files Created/Modified
- path/to/file1 — description

## Decisions Made
[Any decisions that affect future cycles]

## Errors/Blockers
[Anything that went wrong or needs human input]

## Next Cycle Instructions
[Explicit instructions for what the next subagent should do]

Spawning a Mythos-Mode Agent Chain

Via Cron (Automated)

Create a cron job with:

  • sessionTarget: "isolated"
  • model: "deepseek-v4-pro:cloud" (NOT in payload — use routing hint)
  • payload.kind: "agentTurn"
  • payload.message: Start with [ROUTING: MYTHOS-ENGINE] then include task instructions + "Read the latest checkpoint from memory/session-logs/ before starting. If no checkpoint exists, create one."

Via Manual Spawn (Interactive)

sessions_spawn(
  task: "[ROUTING: MYTHOS-ENGINE] [task instructions]. Read latest checkpoint from memory/session-logs/ before starting.",
  model: "deepseek-v4-pro:cloud",
  mode: "run"
)

Continuation Cycle

sessions_spawn(
  task: "[ROUTING: MYTHOS-ENGINE] Continue [TASK_NAME]. Read the latest checkpoint from memory/session-logs/ and continue from where the previous cycle left off. Write a new checkpoint when done.",
  model: "deepseek-v4-pro:cloud",
  mode: "run"
)

Subagent Prompt Quality Standards

Never delegate understanding. The single biggest cause of subagent failure is vague delegation. A subagent has no context from the parent session — it starts fresh. Every prompt must be self-contained and specific.

Bad vs Good Subagent Prompts

Bad: 'Research MedTech competitors and write a report.'
No sources, no format, no scope, no verification criteria.

Good: 'Read the 3 files in memory/research/competitors/. For each competitor, extract: company name, neuroendovascular product line, 2025 revenue estimate, key differentiator. Output a markdown table to memory/research/competitor-summary.md. If any data is missing, write UNKNOWN — never fabricate. Under 500 words total.'

Prompt Template for Every Subagent Spawn

Every sessions_spawn task should include 5 elements:

  1. What: Specific task description with deliverable
  2. Where: Exact file paths for input and output
  3. How: Method, format, constraints
  4. Not: What NOT to do (negative examples prevent common failures)
  5. Verify: How the parent will check the result

Trust But Verify

An agent's summary describes what it intended to do, not necessarily what it did. Always:

  1. Read the output file yourself after the subagent completes
  2. Spot-check specific data points against source material
  3. Never declare 'done' based on the subagent's summary alone — verify the actual output

Parallel Execution

When spawning multiple independent subagents, send them all in a single message so they run concurrently. Do NOT spawn sequentially when there are no dependencies between tasks.

Rules

  1. Always read checkpoint first. If a checkpoint exists, the agent MUST read it before starting work.
  2. Always write checkpoint when done. Even if the task is complete, write a final checkpoint with status: complete.
  3. Never lose progress. If the agent encounters an error, write the checkpoint with status: blocked and explain what happened.
  4. Keep checkpoints under 50K chars. Detailed work goes in separate files; checkpoints are summaries.
  5. Use the MYTHOS-ENGINE routing hint. This ensures the agent gets DeepSeek-V4-Pro with 1M context.
  6. Maximum 10 cycles per task. After 10 cycles, escalate to Roo for review.
